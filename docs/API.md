# REST API v1 and Webhooks

## Authentication

The REST API uses tenant-bound Bearer tokens, not browser sessions. Generate a token in **System Tools → API Tokens**. The raw token is shown once; only its SHA-256 hash is stored.

```http
Authorization: Bearer sp_xxxxxxxxxxxxxxxxx
```

API access is also controlled by the tenant subscription/feature plan.

## Read endpoints

```text
GET /api/v1/customers
GET /api/v1/jobs
GET /api/v1/assets
GET /api/v1/inventory
GET /api/v1/invoices
```

Responses use JSON and are automatically limited to the token's tenant. This release exposes a read API; write operations continue through the permission-aware web/service workflows.

## Webhooks

Configure a name, endpoint URL and event list in **System Tools**. Event deliveries are queued and retried by the cron worker. Payloads are signed using the webhook secret with HMAC-SHA256.

Supported operational events include job creation/completion, quotation approval/sent, invoice creation/overdue, payment, service request, contract/warranty expiry and related system events generated by the application.

Keep webhook endpoints HTTPS, verify signatures and make handlers idempotent.
